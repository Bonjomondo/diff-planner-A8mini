## 时间戳为什么会超前

时间链路为 `FCU IMU → MAVROS 时间转换 → EKF → multipointplan`。MAVROS 根据同步估计的偏移把飞控时钟转换为 ROS 时钟。该估计经过滤波，不是每一帧都与主机时钟精确一致，详见 [MAVROS 1.20.1 时间同步实现](https://github.com/mavlink/mavros/blob/1.20.1/mavros/src/plugins/sys_time.cpp) 和 [时间戳转换实现](https://github.com/mavlink/mavros/blob/1.20.1/mavros/src/lib/uas_timesync.cpp)。EKF 的 `imu_callback()` 将 IMU header.stamp 传给 `system_pub()`，发布到 `/ekf/ekf_odom`；并非人为给该 topic 加了预测时间。

bag 中的关键值：

- 任务中止日志时刻：`1791538910.685905022`。
- 最新 odom 的 bag 接收时刻：约 `1791538910.684134`。
- 该 odom 的 header.stamp：`1791538910.687395334`，与之前收到的 IMU stamp 相同。
- 中止时刻减 odom stamp：约 **−1.490 ms**。
- 临近时刻 `/mavros/timesync_status` 的 estimated_offset 比 observed_offset 高约 **5.80–5.93 ms**。这支持超前源于飞控与主机时钟的估计偏差。
- 17:41:48–17:41:52 共 685 条 odom 中，503 条在 bag 接收时具有负年龄，最大超前约 **4.369 ms**。

bag 的接收时刻是记录节点的时间，不是 multipointplan 回调的精确时刻。原日志没有分项打印保护条件，因此不能直接读取当时每项判定；上述消息时序与代码路径高度一致。

中止附近：飞控仍 connected、armed、OFFBOARD、IN_AIR；FCU state 年龄约 0.580 s，低于 2.5 s 限制；controller state/ready 年龄约 0.096 s，heartbeat 年龄约 0.002 s。CMD_CTRL 时 mission_ready=false 属于预期，运行中的任务不要求该值继续为 true。

旧代码要求 `0 <= 当前 ROS 时间 − odom stamp <= 0.5 s`。任何微小负值都会立刻中止并锁存停止。这是任务保护对跨时钟消息缺少容差的 bug；并不表示 odom 停更或位置估计失效。

## 修复

- 仅 odom header 时间校验允许小幅超前，默认 `odom_future_tolerance_sec=0.02`，合法消息年龄为 `[-0.02, 0.5] s`。
- 接收时间、控制器与 heartbeat 的校验仍严格，odom 超过 0.5 s 未更新、零时间戳、非有限位置/速度、坐标系错误、大幅超前仍会被拒绝。
- 参数必须有限、非负，且不得超过 odom timeout；可设为 0 恢复严格判定。
- 将原来的合并中止提示拆成 odom、controller/FCU、heartbeat 三类，并打印时间年龄与相关状态。
- 保留原 IMU/EKF 时间戳与同步逻辑，避免改变传感器融合的时间对齐。

20 ms 是覆盖本次约 4.4 ms 超前并留出余量的有界默认值，不是对所有同步异常的保证。实际飞行仍需确认新日志中的时间戳偏差在该范围内。
