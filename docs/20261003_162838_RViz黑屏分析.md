## 诊断采集器启动后立即退出

[host_metrics.jsonl](../flight_logs/20261003_162838/host_metrics.jsonl) 只有一条退出记录：

```text
16:28:39.614 collector_exit reason=parent_exited
```

原因是启动链为：

```text
debug launcher → process_supervisor.py → flight_diagnostics.py
```

传入 `--parent-pid` 是 debug launcher 的 PID，但旧代码用 `os.getppid()` 与之比较，得到的实际上是 supervisor 的 PID。采集器因此误判 launcher 已退出，在正式启动 ROS 前就关闭了 tegrastats/ping。

本次没有持续 CPU/GPU/内存指标，不能据此声称“GPU 被 YOLO 占满”或“内存不足”。另外 dmesg 无读取权限，kernel 日志也缺少有效内容。

已改为检查指定 launcher PID 是否仍存在。回归测试使用真实 supervisor 启动 collector，要求运行期持续产生采样，并验证退出后探针子进程已回收。supervisor 收到清理 TERM 时返回 143，这是正常的信号退出状态，不等同于采集器异常。
