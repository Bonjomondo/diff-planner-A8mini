# 地面站航点云台自动动作与转速

更新：2026-11-06。适用分支：`feat/gcs-dynamic-mission`，工程 `/home/ly/Documents/diff-planner-A8miniV2`。

远程航点现在可以携带云台动作：到点确认位置和速度稳定，悬停，转到指定角度或做水平扫描，等待画面稳定，按需拍照，得到动作结果后再飞下一点。只启动云台节点不会自动转动；上传航线也不会起飞或开始任务。

本次已完成源代码同步、`multipoint` 包编译、隔离环境联调和不飞行的云台小角度实机回读。隔离环境使用模拟飞控状态与 dry-run 云台，不能作为实飞验收。生产飞行执行器与网关需一起重新加载新消息定义；已经运行的进程不会因文件更新而自动替换。本次另外通过模块管理器按原有选项执行了落地未解锁检查后的 `--start-only` 更新启动，结果见 [管理重启记录](20261106_云台协议机载管理重启.json)；没有发送起飞、解锁或开始航线命令。

## 从地面站使用

1. 在“机载程序”启动“云台控制”；按需要另选“飞行栈”。自动录像仍是独立选项。
2. 在室内航点编辑中为所需航点选择“定角”或“水平扫描”，配置角度、转速、稳定等待和拍照选项。无动作航点保持不启用云台。
3. 核对坐标与本轮定位，上传航线并取得机载确认。云台角度以机身/相机安装方向为参考，不随地面站地图坐标校准而旋转。
4. 按原有流程手动起飞悬停，再明确开始任务。到点后飞行状态保持“到点悬停”，另显示云台动作阶段。
5. 动作期间由机载执行器负责转动；地面站手动云台操作应锁定，避免两套指令争用。

“水平扫描”是先到最小水平角，再扫到最大水平角。勾选拍照时只在**最终端点拍一张**，并非左右端点各一张，也不是连续录像。连续录像由录像功能单独控制。

## 参数与方向

| 参数 | 范围/默认值 | 含义 |
| --- | --- | --- |
| `mode` | `angle` / `sweep` | 定角 / 水平扫描 |
| `yaw_deg` | −135～135°，默认 0 | 定角目标；向右为正 |
| `pitch_deg` | −90～25°，默认 0 | 俯仰目标；向上为正，朝下为负 |
| `yaw_min_deg` | −135～135°，默认 −45 | 扫描起点 |
| `yaw_max_deg` | −135～135°，默认 45 | 扫描终点，必须大于起点 |
| `speed` | 整数 1～100，默认 30 | SIYI SDK 转向速度等级，**不是 °/s** |
| `settle_sec` | 0～10 s，默认 1 | 转到目标并确认后，额外稳定等待 |
| `photo` | 布尔值，默认 false | 在最终角度稳定后触发一次拍照 |

速度作用于自动动作的水平/俯仰闭环上限。接近目标时自动减小速度，用真实姿态回报判断是否到位。实机发现过低的近目标速度不能克服机械静摩擦，因此闭环近目标使用不超过用户上限的最低有效指令等级 10；用户上限小于 10 时仍严格保留该上限。低速或大范围动作可能超过 60 秒执行期限并报错，不会静默跳过。

协议依据为目录内 [SDK V0.1.1](<SDK - V0.1.1.pdf>) 的 0x07、0x0B、0x0C、0x0D 命令说明。0x07 为 −100～100 的转向速度，0 停止；0x0D 姿态原始 yaw 与地面站右正方向相反，因此机载远程执行器会统一取反。旧 YAML 预设任务的历史角度含义保留；本文描述的是新远程航点接口。

## 远程航点格式

保持 JSON-lines protocol 2，给有动作的航点增加可选 `gimbal` 对象。不执行动作时完全省略该字段，旧的纯航点任务保持原行为。

```json
{
  "id": 1,
  "x": 1.0,
  "y": 0.0,
  "z": 1.0,
  "hover_sec": 2.0,
  "gimbal": {
    "mode": "angle",
    "yaw_deg": 30.0,
    "pitch_deg": -20.0,
    "yaw_min_deg": -45.0,
    "yaw_max_deg": 45.0,
    "speed": 25,
    "settle_sec": 1.0,
    "photo": true
  }
}
```

上传与更新仍校验 `map_session_id`、`mission_id`、`revision` 和冻结前缀。正在执行动作的当前航点不能被替换；允许更新它之后的航点。网关单帧仍限制 64 KiB、最多 200 航点；动作字段增加体积后，以实际编码大小为准。

遥测 `mission.gimbal_capabilities.version=1` 表示接口支持，`gimbal_ready` 表示对应云台节点心跳新鲜，`gimbal_required` 表示剩余航线需要云台。节点心跳不等同于相机已验证可控；相机无响应会在动作执行中报错。`gimbal_dry_run` 明确标出模拟云台；生产执行器默认不接受模拟节点开始云台航线，只有隔离测试显式启用 `allow_gimbal_dry_run`。

动作阶段为 `idle`、`moving`、`settling`、`photo_sent`、`complete`、`failed`；详情在 `action_reason`。主任务状态继续使用 `HOVERING`，完成动作后再增加航点完成计数。

## 动作确认和中断

- 内部 `GimbalTask` / `GimbalResult` 使用本轮地图、任务、航点和独立动作 ID 关联。旧版仅含航点编号的 `/mission/gimbal_done` 不会完成远程动作。
- 每个云台进程有独立代号。执行器重启后拒绝旧进程的任务，防止重启后再次按下快门。
- 重发只刷新租约或取回缓存结果，不重新拍照。执行器每 0.5 秒用独立 wall timer 刷新 5 秒租约，和旧预设任务的 `gimbal_retry_sec` 无关。
- 每次可能阻塞的姿态查询前先发零速度。录制查询/切换与远程动作共享完整执行期间的互斥锁，不能阻挡正在转动时的停止帧。
- 在目标容差内连续读到姿态后才开始稳定等待；稳定等待结束后只读复核。发生漂移时直接失败，不暗中补转后立即拍照。
- 拍照 0x0C/00 本身没有 ACK；执行器只发一次，等待 0x0B 的成功/失败反馈。无反馈报告“结果未知”，不重发快门、不继续航线。成功表示相机反馈成功，不能替代存储卡文件完整性核验。
- 定位/飞控/规划器状态失效、离开悬停容差、节点心跳丢失、租约失效、返航或降落/重置会取消当前动作并停止转向。原有飞行失败锁存、降落与复位流程保留。

## 共享相机中转

动态任务的 `gcs_payload.launch` 默认 `camera_host=127.0.0.1`、`camera_port=37260`，经 `siyi-gimbal-relay` 共享同一个上游相机 socket，也保留转向失联停止保护。应使用支持“最近客户端回包分发”的新版中转，否则地面站轮询和机载节点会抢走彼此应答。

历史预设启动方式仍可显式配置直连相机；需要与地面站同时使用时，应统一经中转，避免相机单客户端返回地址反复切换。
