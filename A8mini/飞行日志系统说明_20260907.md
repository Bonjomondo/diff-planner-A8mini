# 飞行日志系统补全与使用说明

本次补全针对 `20260906_183832` 暴露的证据缺口：黑屏时缺少同一时刻的主机负载、相机链路状态、采集进程状态，以及实际运行依赖版本。修改保留原飞控、云台、模型和取流配置，诊断独立运行，不发送相机控制或飞行指令。

## 1. 运行方式

照常使用工作区中的调试脚本，新日志默认开启：

```zsh
source devel/setup.zsh
zsh sh_files/run_single_lio_debug.sh
```

日志仍写入 `flight_logs/YYYYMMDD_HHMMSS/`。完整主机采样只在**调试脚本**中开启；直接使用原 `run_single_lio.sh` 不会开启主机诊断。检测自身的时间戳、事件和计数始终输出；检测环境快照仅在设置 `UAV_DEBUG_LOG_DIR` 时保存，调试脚本会自动设置它。

## 2. 新增或增强的文件

| --- | --- | --- |
| `host_metrics.jsonl` | 每核/全机 CPU 与 iowait、负载、内存、磁盘计数与剩余空间、网卡累计流量/错误/丢弃/链路状态、TCP 全局计数、关键进程及其采集子进程 CPU/RSS/线程数/I/O/等待位置、温度与可用的压力指标 | 默认每 1 s |

| `console.log` 中 `[RTSP]` | 连接代次、采集 PID、首帧恢复、距上次合格帧间隔、进程退出码及原因 | 连接/退出事件 |

## 3. 怎么对齐和理解这些数据

**同一台机器、同一次启动内，优先用 `monotonic_sec` / `mono=` 对齐间隔，用带时区的墙钟或 `unix_sec` 对齐 ROS/rosbag。** 单调时钟不跟随系统时间校正，boot ID 用来区分不同开机；墙钟发生跳变时，不要直接将两条墙钟时间相减当持续时长。

- JSONL 一行一个 JSON 记录。主机采样同时记录实际采样间隔 `sample_interval_sec`、采集开销 `sample_cost_ms`；TCP 工具单独记录 `socket_probe_cost_ms`。调度变慢或工具超时会导致实际间隔大于 1 s，数据里不会假装仍是固定周期。
- 检测器自己产生的日志有源头时间；外层 `[DETECTION_PROCESS]` 是监管进程接收时间。原生库如果自身缓冲了输出，外层时间不等于错误精确发生时间。内核日志可能包含启动前历史消息，应结合行内内核时间，不能全部当作刚发生。
- `cpu_percent_one_core=100` 表示占满**一个核**，多线程进程可大于 100；全机/每核 `busy_percent` 是采样区间 CPU 计数推导值。首次采样、PID 重用、计数器复位或不能计算时填 `null`，不伪造为 0。
- `skipped_capture_frames` 是“最新帧模式下没有送入本轮推理的、能由序号跳变确认的帧数”，包括主动限频/慢消费造成的跳过；**不是网络丢包数**，也不包含重连时所有无法观察到的帧。
- `frames_received` 是采集器通知监控线程的合格帧累计值；`since_last_fresh_ms` 即使重连也保留无合格帧的时间线。`window_max` 的 CAP/YOLO/AGE 来自检测器实际取到的帧，读流失败的耗时看对应错误事件。
- AGE 仍是 read 开始到当前处理阶段的**本地**年龄，不包含相机曝光/编码或网络内部缓存。首帧 `gap_sec` 是合格帧之间的间隔，不是逐屏幕测量的黑屏时长。
- 网卡及 `/proc/net` 计数是本机/接口汇总，不能全部归到相机；相机 TCP 快照和 ping 用于辅助区分。ping 通也不保证 RTSP 服务和解码正常，短于采样间隔的故障可能漏过。
- Jetson 功耗/温度来自主板可见传感器，不能代替相机端供电测量；没有某项输出不能解释为该项为零或一定正常。

Linux 计数口径参考 [内核 proc 文档](https://www.kernel.org/doc/html/latest/filesystems/proc.html) 和 [磁盘 I/O 计数文档](https://www.kernel.org/doc/html/v6.7/admin-guide/iostats.html)；Jetson 输出字段以 [NVIDIA tegrastats 文档](https://docs.nvidia.com/jetson/archives/r36.5/DeveloperGuide/AT/JetsonLinuxDevelopmentTools/TegrastatsUtility.html) 及目标机实际版本为准。

## 4. 开销、容量和失败处理

采集器使用 Python 标准库，默认 1 Hz，以 nice +10 运行；不额外打开 RTSP，不加载第二份模型，不录制原始视频或默认打开雷达原始数据。相机网络探测仅 ICMP，TCP 状态读取来自本机内核。

四种新增周期日志（host、tegrastats、ping、kernel）**各文件默认 20 MiB，保留 2 个轮转备份**，即每种最多约 60 MiB，总共约 240 MiB；轮转名是 `.1`（较新）、`.2`（较旧）。轮转会覆盖最旧诊断记录，长时测试需按所需覆盖时长调大上限。启动快照不随周期日志轮转。**此限额不包含已有 console.log、ROS 日志和 rosbag**；没有自动删除历史飞行目录。

日志分文件逐行刷新，不逐样本 fsync。剩余空间低于 256 MiB 时停止新增诊断采集以减少额外负担，但不会停止既有 rosbag/飞行进程，因此不能当成全盘空间保护。磁盘写入失败会记录告警并关闭对应诊断写入；工具缺失、内核接口不存在或读取权限不足会明确留下 `unavailable`、错误输出或退出码。内核采集先尝试直接读取，再尝试 `sudo -n`，绝不在后台等待密码；失败不阻止飞行栈启动。

Ctrl+C/正常收尾时，采集器结束自己启动的 ping、tegrastats、dmesg 并记录退出状态，不使用会影响其他会话的 `pkill` 或 `tegrastats --stop`。调试父进程消失时，采集器下一轮检查也会结束。强制 SIGKILL、掉电或文件系统本身卡死仍可能来不及写最后一条退出记录。

## 5. 可调开关

| 环境变量 | 默认 | 用途 |
| --- | --- | --- |
| `UAV_DEBUG_DIAGNOSTICS` | `1` | 设为 0 关闭新增主机诊断，原有日志和检测日志保留 |
| `UAV_DEBUG_DIAG_INTERVAL` | `1` | 主机/Jetson 采样秒数，最小 0.5；相机 ping 仍固定 1 s |
| `UAV_DEBUG_DIAG_MAX_MB` | `20` | 每种周期日志单文件 MiB 上限，另有两个备份 |
| `UAV_DEBUG_CAMERA_IP` | `192.168.144.25` | 当前相机地址；修改相机配置后应同步此项，启动 manifest 会记录实际探测目标 |
| `UAV_DEBUG_CAMERA_PING` | `1` | 设为 0 不发 ICMP，其余本机诊断保留 |
| `UAV_DEBUG_DIAG_PROBES` | `1` | 设为 0 只读取 proc/sysfs，不运行 ping/tegrastats/dmesg/ip/ss |

示例：提高采样间隔并扩大轮转范围：

```zsh
UAV_DEBUG_DIAG_INTERVAL=2 UAV_DEBUG_DIAG_MAX_MB=40 zsh sh_files/run_single_lio_debug.sh
```

只验证日志采集器、不启动 ROS/飞控/模型的本机检查：

```zsh
/usr/bin/python3 sh_files/flight_diagnostics.py \
  --log-dir /tmp/flight_diagnostics_check --duration 10 --no-probes
```

## 6. 下次黑屏时如何判读

1. 从 `console.log` 的等待/重连事件取出时间和采集 PID，在 `host_metrics.jsonl` 中查相邻秒的数据。
2. 如果合格帧数停止增加、推理没有长耗时，但 ping、网卡 carrier、TCP 重传或内核链路事件异常，先查相机公共链路；再对齐云台 0x0E 超时。
3. 如果采集仍持续有帧，YOLO 最大耗时/过期结果计数升高，同时 CPU/GPU/内存或 I/O 压力升高，优先查主机资源与推理。
4. 如果网络证据正常而 HEVC 参考帧错误持续，保留这一段源码/配置/解码器版本，进一步做码流或抓包对照；现有轻量日志不能代替码流内容。
5. 查看 `worker_exit`、检测监管退出码和 `collector_exit`，区分一次重连、检测进程退出和日志采集器自身不可用。若整机突然掉电而没有退出记录，再结合开机内核日志和供电测量。

## 8. 权限与参数快照修复（2026-09-07 后续）

当前机载电脑的用户 `q` 已安装只读免密规则 `/etc/sudoers.d/a8mini-kernel-log-q`，固定辅助程序为 `/usr/local/libexec/a8mini-kernel-log-reader`（root 所有）。只授权内核读取，不授权任意命令或清空内核日志。新增实现没有保存密码，也没有让整套飞行程序以 root 运行。

换电脑或更新辅助程序时，一次性执行：

```zsh
sudo bash sh_files/install_kernel_log_access.sh q
```

辅助程序通过标准输入管道感知日志程序退出，负责结束并回收自己的 `dmesg` 子进程。普通用户直接终止提权进程会遇到权限错误，因此不采用该方式。`diagnostics_manifest.json` 的 `kernel_access.mode` 标记 `direct`、`sudo_read_only` 或 `unavailable`。

参数转储新增 `rosparams.initial.yaml` 和 `rosparams.final.yaml`。主快照 `rosparams.yaml` 等待 `/multipointplan` 注册且 `/multipointplan/yaml_path` 可读取后保存；这用于确认当前 launch 的参数加载阶段完成，不代表飞行状态或相机已健康就绪。最多等待 120 秒，可通过 `UAV_DEBUG_SNAPSHOT_TIMEOUT` 设置；超时保存部分参数，并在 `snapshot_status.log` 标记 `timeout_partial`，转储退出码也记录在该文件中。提前退出时仍尝试保存结束快照。

本次 **10 项日志测试通过**，包括延迟加载参数、权限失败/免密回退和关闭管道回收进程。地面真实权限环境读到 **964 行内核日志**，辅助进程退出码 **0**；未启动真实飞行栈。收尾阶段忽略重复 Ctrl-C，避免再次打断 rosbag 摘要等归档动作。
