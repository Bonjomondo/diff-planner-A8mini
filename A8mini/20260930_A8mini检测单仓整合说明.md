## 启动和更换模型

保持任务配置中的 `enable_gimbal: true` 与 `enable_realtime_detection: true`，再按实机指南启动 LIO/VIO 任务。只检查检测链路时可运行：

```bash
source devel/setup.bash
roslaunch multipoint a8mini_detection.launch
```

默认 launch 参数会从 `$(find multipoint)/models/yolo11s.engine` 载入模型。直接启动检测 launch 时可用 `model:=/绝对路径/模型.engine` 切换模型；配套类别表必须与模型同目录同基名，例如 `custom.engine` 对应 `custom.names.json`。类别表缺失、含占位名称或类别编号不连续时，检测会在加载推理环境前报错。

引擎是 TensorRT 序列化产物，移到不同 JetPack、TensorRT 或 GPU 环境后需要确认兼容性。当前仓库没有附带原始 `yolo11s.pt`，若目标机不能加载该引擎，需要从可信的原始权重重新导出，并同步生成类别表。目标机仍需安装与 Jetson/CUDA/TensorRT 匹配的 Python、PyTorch、Ultralytics 和 OpenCV；单仓整合不等于把这些系统运行库一并打包。

本机检测配置使用工作空间根目录的 `.venv-a8mini/bin/python`。该环境是为恢复本机运行从既有环境复制的，已加入 `.gitignore`，不会随 Git 克隆；其他机器应重新安装匹配自身 JetPack 的推理依赖，并修改 `config/a8mini_detection.yaml` 的 `python_executable`。

## 诊断记录

运行时快照保存在 `UAV_DEBUG_LOG_DIR/detector_runtime_<PID>/`。manifest 记录模型路径、大小、修改时间和 SHA256；源码快照包含本仓库检测、采集、录像、诊断、标签辅助脚本，以及所用 `.names.json` 的 SHA256。模型引擎本身不复制进每次飞行日志。

最初整合时完成了检测单测、独立 catkin 编译与 install 布局检查，以及 launch 模型参数展开检查。后续本机实测结果见下节。历史故障和这次整合的关系见 [2026-09-29 全问题诊断报告的后续记录](../docs/20260929_全问题诊断报告.md) 和 [2026-09-06 断流核对的后续记录](20260906_183832日志分析与修复报告.md)。
